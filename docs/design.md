# epa-drinking-water-mcp-server

## Scope and decisions

Provide a keyless, read-only research workflow over EPA public water system inventory, historical SDWA violations, enforcement actions, Lead and Copper Rule summaries, and UCMR 5 occurrence measurements. Serve researchers, journalists, utility analysts, and people investigating the systems serving their area. A record is evidence about the EPA publication, not a tap-water safety verdict or a statement of present compliance.

The workflow is reference → find a system → inspect its profile → retrieve violations, enforcement, or measurements → stage analytical partitions → describe → query. All nine tools are standard tools. No authored EPA data resources, prompts, MCP Apps, user-data store writes, arbitrary URL inputs, or upstream mutations are required. The SDK serves the published caller guide through its Skills extension and resource interface.

Use paged DMAP for SDWIS, the national UCMR 5 ZIP for occurrence, and a small bundled reference for regulatory terminology and source links. Do not download the national SDWA bulk ZIP at runtime: its 558 MB compressed payload is disproportionate to a scoped request. Paged, resumable analytical partitions support multi-year analysis without pretending that one bounded call acquired a national warehouse. Inventory searches remain discovery results rather than automatic canvas spills.

EPA publishes these for public download and analysis. No API key, per-user credential, or documented numerical request rate is required. Do not imply that every state-submitted field is necessarily an EPA-authored public-domain work; retain EPA attribution and source links. No explicit additional AI-use or caching prohibition was identified on the source pages. Drop operator contacts before any cache, log, response, or canvas registration.

Every source-bearing result includes `provenance`: source name and public URL, `retrieved_at`, optional `last_modified`/`etag`, `snapshot_quarter` only when explicitly present in the source, effective filters, and caveats. HTTP retrieval time is not observation time or snapshot time. Never infer a DMAP snapshot quarter from today's date or copy a quarter from a different table. Association rows can carry `submissionyearquarter` when base tables do not.

All SDWIS results state: “SDWIS is a quarterly publication of reported records; missing or resolved historical records do not establish current compliance or water safety.” UCMR results state: “UCMR 5 occurrence results are not compliance monitoring; a missing result does not mean a contaminant is absent.” MRL is a reporting threshold, not a health threshold. Do not emit a synthetic risk/severity score, safe/unsafe flag, inferred violation, or current-compliance status.

## Verified upstream behavior

Design verification on 2026-10-25 established the following implementation requirements. Concrete water-system examples below are synthetic; real probe payloads are not shipped.

* DMAP returns a JSON array of lower-case field names, with numbers for measured values/counts and JSON `null` for unavailable fields. Date strings use `YYYY-MM-DD HH:mm:ss`, including nonmidnight times. Normalize the source calendar day without timezone inference and retain nonmidnight source text in a companion `_raw` field.
* Sorted `1:2` and `2:3` overlap by exactly the second identity. Ranges are one-based and inclusive. `0:0` aliases the first record and must not drive pagination. Use `1:page_size`, then `page_size+1:2*page_size`. Put `sort` before the range; putting it after the range produced HTTP 500. Composite sorting requires an explicit direction on every column, such as `sort/pwsid:asc,violation_id:asc`; directionless comma lists return HTTP 500.
* `equals`, `contains`, `beginsWith`, `greaterThan`, `greaterThanEqual`, conjunction `and`, and comma-separated `in` have reachable paths. `startsWith` and a misspelled column produced HTTP 500. Only verified spellings are emitted. Recheck each returned predicate against row values; an ignored filter is a schema/contract failure, never a successful broad result.
* A valid unassigned PWSID returns HTTP 200 `[]`; malformed IDs are rejected locally. PWSIDs include numeric tribal prefixes and alphabetic suffix characters. Two letters followed by seven digits is too narrow.
* County records can have `state_served=null` while `county_served` and `primacy_agency_code` are populated. `state_served=<state>` therefore cannot be used to select a state's county service areas. A PWSID state-letter prefix also omits tribal-administered systems physically in that state.
* UCMR archive metadata: 13,531,598 compressed bytes, Last-Modified 2026-10-15; 342,858,685 uncompressed bytes including PDFs. `UCMR5_All.txt` contains 1,991,977 rows: 1,934,476 use sign `<` and a blank value; 57,501 use `=` and a numeric value. Censoring is the common case, not an exception. All observed measurement units are `µg/L`.

## Data contracts

Parse upstream JSON/TSV at the boundary using Zod. Required identity fields must exist and be nonempty; sparse descriptive fields are nullable/optional and stay unknown. Preserve code strings and leading zeros. Do not stringify missing data into a code, coerce empty numeric fields to zero, or treat unknown Y/N flags as false. Date parsing is strict and validated; output dates are ISO calendar dates with the raw date retained when meaningful. Numeric zero from the source remains zero, but `state_mcl=0` is not interpreted as a federal zero-tolerance standard.

The public system projection is an explicit allowlist. Omit `admin_name`, `org_name`, address lines, contact city/ZIP, `email_addr`, phone/fax/extension fields and alternate numbers. The `water_system` projection also preserves `is_school_or_daycare_ind` and `is_wholesaler_ind`, including null or absent values, in discovery and profile summary output. The optional discovery boolean `school_or_daycare` selects exactly Y or N; both booleans count as narrowing selectors and unknown indicators match neither. It identifies reported systems, not every school/daycare receiving public water. Do not infer a boolean from a missing source indicator.

### UCMR 5

`UCMR5_All.txt` headers, in order: `PWSID`, `PWSName`, `Size`, `FacilityID`, `FacilityName`, `FacilityWaterType`, `SamplePointID`, `SamplePointName`, `SamplePointType`, `AssociatedFacilityID`, `AssociatedSamplePointID`, `CollectionDate`, `SampleID`, `Contaminant`, `MRL`, `Units`, `MethodID`, `AnalyticalResultsSign`, `AnalyticalResultValue`, `SampleEventCode`, `MonitoringRequirement`, `Region`, `State`, `UCMR1SampleType`.

`UCMR5_AddtlDataElem.txt`: `PWSID`, `FacilityID`, `SamplePointID`, `SampleEventCode`, `AdditionalDataElement`, `Response`, `IfOtherText`. `UCMR5_ZIPCodes.txt`: `PWSID`, `ZIPCODE`.

Use `TextDecoder('windows-1252')` incrementally; UTF-8 decoding corrupts the micro sign. Parse tabs, quoted fields, CRLF and embedded text correctly rather than splitting every line on tabs. ZIP extraction uses an audited streaming ZIP reader and strict allowlisted entry names, never filesystem extraction. Add `yauzl` for lazy entry streams and `csv-parse` for streaming TSV parsing; use their typed APIs and independently verify maintained versions at implementation time. Stream compressed bytes to a private temporary file, inspect central-directory sizes and CRCs, then stream only the three named TSV entries. A 32 MiB compressed/400 MiB total expanded ceiling accommodates the verified archive; fail `dataset_changed` rather than silently dropping rows if the publication exceeds it. Remove the server's temporary file on success, error, cancellation and teardown. No bulk archive is bundled in npm or MCPB.

Normalize all occurrence columns to snake_case. IDs, `size`, `region`, `state`, signs, codes and names stay strings; `collection_date` becomes a strict ISO date from `M/D/YYYY`; `mrl` is a finite number; `analytical_result_value` is a finite number or null. Preserve `analytical_results_sign`, and expose `censored: true` only for `<`. A censored blank value stays null, never zero or half-MRL. Preserve `µg/L`; any requested display conversion to `ng/L` must explicitly report factor 1000 and retain original units/value. The tool itself defaults to original units and does not calculate exceedances.

Join ZIPs by PWSID as a distinct membership table, not by multiplying measurement rows. Additional elements join on `(pwsid, facility_id, sample_point_id, sample_event_code)` and remain a separate one-to-many table. A result identity includes PWSID, facility, sample point, sample ID, collection date, contaminant and method; preserve distinct source rows rather than silently deduplicating analytical replicates. The archive's `State` includes tribal/region-like codes; a reported-state filter resolves IDs through WATER_SYSTEM `state_code` and intersects them, rather than assuming every value is a postal state.

## Inputs, pagination and output envelope

Use flat root objects so clients retain all mode fields. Normalize whitespace and case for codes, state abbreviations/names, exact contaminant aliases and PWSIDs. PWSID accepts `/^[A-Z0-9]{9}$/` after uppercase/trim, including numeric prefixes; do not restrict to a guessed list of prefixes. A valid unknown ID is a result. Reject punctuation, shortened IDs, URLs, or ambiguous names in ID fields. States normalize through a bundled complete postal-state/territory map. `state` means the reported WATER_SYSTEM legal-entity state, not a guaranteed physical service boundary; echo `state_basis: reported_legal_entity` whenever used. `primacy_agency` and `pwsid_prefix` are separately named reference-supported selectors. County requires state; strip a terminal “ County” for comparison, but preserve source spelling. Do not infer a county from a mailing city or ZIP. Accept real `YYYY-MM-DD` dates or `YYYY-MM-DD HH:mm:ss` timestamps, normalize both to their calendar day, and reject reversed ranges. Advertised raw-input patterns preserve trimming, case normalization and optional blank values; semantic validation still checks real dates and normalized identifiers.

Contaminant aliases are exact and case-insensitive: lead → SDWIS `1030,5000`, arsenic → `1005`, nitrate → `1040`, TTHM → `2950`; LCR lead/copper summaries use `PB90`/`CU90`. Code `5000` covers Lead and Copper Rule records, including copper and monitoring records; an explicit `1030` or `5000` still selects only that code. Preserve the comma-separated scalar in `effective_filters.contaminant`. Four-character alphanumeric violation codes pass through unchanged after case normalization, including codes absent from the current dictionary; do not zero-pad or freeze upstream vocabulary into an enum. `1022` is “COPPER, FREE”, not a substitute for `CU90`. PFAS is a UCMR family selector (29 analytes); lithium is separate; PFOA/PFOS/HFPO-DA and other exact UCMR names resolve through the archive catalog. Ambiguous group names are rejected with reference guidance, never fuzzily assigned a code.

The bundled `standards` topic starts with these reviewed reference values from the EPA standards page, checked 2026-10-25: arsenic MCL 0.010 mg/L (applicable from 2006-01-23), MCLG 0; nitrate as nitrogen MCL/MCLG 10 mg/L; TTHM MCL 0.080 mg/L with no group MCLG; copper action level 1.3 mg/L and MCLG 1.3 mg/L; lead legacy action level 0.015 mg/L and MCLG 0. Each entry distinguishes `mcl`, `mclg`, `action_level`, and `treatment_technique`; unknown applicability dates are null with the rule link, never invented. The lead entry is explicitly the legacy LCR comparison reference, not a universal current threshold; newer rule applicability must be reviewed before adding another dated entry. PFAS entries link to the current EPA rule/implementation pages and note pending rule changes, without calculating compliance from UCMR results. Reference values are context only; the server never labels a historical row an exceedance by comparing it to this table.

Common output: `effective_filters`, `items`, `returned`, `limit`, `has_more`, optional `next_cursor`, `source_complete`, optional exact `total`, `provenance`, `notices`, optional `dataset`. Omit `total` unless counted over the full matching selection; `returned` is never advertised as total. `source_complete` means the entire selection is contained in this response or its staged partition. A complete first staged partition can have a smaller inline preview. Once earlier pages or partitions have delivered rows, later outputs conservatively remain incomplete even when retrieval reaches the end; combining every partition does not upgrade that flag. `has_more=false` independently means retrieval is exhausted. `has_more` describes the specific continuation and its `phase` (`membership`, `source`, or `preview`). Cursors are opaque authenticated tokens or unguessable process-local handles binding normalized filters, ordering, source offsets/batch state and expiry. UCMR binds the archive hash; DMAP binds the retrieval job and any available source metadata, not an invented snapshot revision. Changed filters cause `cursor_invalid`; a changed archive hash or detected DMAP metadata change causes `source_changed`. Undetectable DMAP publication changes remain possible and are disclosed as non-atomic consistency. Restart invalidates continuations. Do not store cursors in a user-data store.

Every `limit` defaults to 10 with an effective maximum of 500 whole rows, or whole tables for describe. Ready pages return `min(limit, available rows)`; byte size never shortens a page. Bounded source-work checkpoints can return fewer rows with exact continuations and conservative completeness. Staged previews return `min(limit, staged rows)`. Profile summary remains a separate `system` with empty `items` and `returned:0`.

`SDWIS_CLAMP_LIMITS` defaults true and is parsed with `z.stringbool()`. In clamp mode, advertise positive integers without a schema maximum and clamp over-cap `limit` requests with a notice, one log entry and one counter increment per clamp. False advertises and enforces `maximum:500`. Nonpositive/fractional values remain invalid. Source `stage_max_rows` retains its default 5000 and effective maximum 25000 with a notice when clamped. Preserve complete Unicode/markup rows and equivalent `content[]` and `structuredContent`; no byte-packing or oversized-record text mode is exposed. Strict validation rejects legacy text-recovery inputs. Dataframe outputs have no paging phase; source continuations retain `membership`, `source` and `preview` phases.

## Workflow and retrieval implementation

### Geographic membership

Names match literal case-insensitive substrings, and normalized counties match exactly. For unsafe names, push down `contains` on the longest nonblank grammar-safe run, treating `_` as unsafe for substring operators; omit the predicate when no run exists. For unsafe counties, push down `beginsWith` on the leading safe run or omit it. Apply the complete selector locally before buffering inventory rows or inserting geographic membership, including UCMR membership. Preserve terminal `County` removal and reject control characters. Recheck the predicate actually sent upstream; broadened pushdown is only a candidate search, never the final match.

Resolve reported state using WATER_SYSTEM `state_code=...`, with all activities when an analytical call does not specify activity. EPA defines this as the legal entity's USPS state; a live joined record had a different PWSID jurisdiction prefix, so it must never be described as physical location. The discovery default `active` applies only to discovery and is echoed. County resolution uses GEOGRAPHIC_AREA `county_served=...`, then intersects distinct PWSIDs with reported-state inventory. This can include tribal-administered systems, but is not a complete map of systems physically serving the requested state. Every county/state result discloses that limitation and the match basis; a county name alone does not establish a state-qualified county boundary. `primacy_agency_code` and PWSID prefix are jurisdiction selectors only. Resolve ZIP through distinct SDWIS/UCMR service memberships, never operator ZIP. No service-area match asserts that every measurement was collected there.

Materialize the complete distinct ID set as paged bounded work, then query fact tables with `pwsid/in/<up-to-50-ids>` and verified fact predicates. This avoids fragile multi-table DMAP joins and keeps public projections explicit. Persist only ephemeral process-memory job state bounded by TTL and size; no `ctx.state` writes. If membership is not exhausted within a call, return a continuation in membership phase and no apparently complete facts. Reserve five seconds of the shared work budget for checkpoint serialization; abort and await an unfinished membership read, then resume that uncommitted page on the next call. Caller cancellation and upstream failures remain errors. Never apply county filtering to a page already cut from a national fact query.

Read DMAP pages of 1000 rows, sequentially paced, and stage at most 25000 fact rows per call; clamp higher staging requests and disclose continuation. The source loop starts another page only while its accumulated page count is below 17; completing that page's label dictionaries can raise the count further. All reads share the 45-second deadline. Membership jobs cap at 100000 systems, 100 live jobs, 15-minute idle TTL, with an explicit capacity failure and narrower-scope guidance. Date interval overlap is checked locally against source dates, so a narrow date range can still require multiple source pages. A known endpoint inside the requested interval proves overlap even when the other endpoint is null; missing endpoints never imply an indefinitely open period. Exclude indeterminate overlap and report the excluded count only for rows examined during that call, never as a total for the selection. Retrieval jobs retain validated contact-free rows within a 64 MiB process budget and expire after fifteen idle minutes; code labels have a separate one-hour cache. Completed selections are not reused across independent jobs.

Sort DMAP by source identities: water systems `pwsid`; violations `pwsid,violation_id`; actions `pwsid,enforcement_id`; LCR samples `pwsid,sample_id`; results `pwsid,sample_id,sar_id`; reference `value_type,value_code`; treatment `pwsid,facility_id,treatment_id`. Geographic/service rows without unique keys use all projected source columns as tie-breakers; retain multiplicity. Detect repeated pages and overlapping boundaries only where source keys are unique; identical projected rows in other tables can be legitimate duplicates. Compare available publication metadata across pages, without refetching earlier boundaries. Offset pagination is not a transactional snapshot: return `consistency: quarterly_non_atomic` even when exhausted. A detected metadata change invalidates the job, but changes without validators can remain undetected. Source exhaustion is not a guarantee that EPA holds every real-world event.

### System profiles

Profile facilities sort by `pwsid:asc,facility_id:asc` and use the unique `(pwsid, facility_id)` key for paging validation. An optional exact `facility_id` is trimmed with blank treated as unset; unlike PWSID, this opaque identifier permits literal punctuation through safe candidate pushdown and local matching. A nonblank selector on another section fails `invalid_selector` before HTTP. Resolve labels through `FACILITY_TYPE_CODE`; unknown codes retain null labels and source codes. System columns remain in summary.

### Violations, LCR and enforcement

Violation retrieval applies PWSID and verified code predicates upstream, then inclusive compliance-period overlap locally. Do not classify every lead-code record as an exceedance: monitoring/reporting categories can have no measured concentration. Preserve health-based and major indicators as source values. Resolve labels from `(value_type,value_code)`; unknown labels remain null with the code intact.

LCR retrieves sample results and sample periods separately, joining by `(pwsid,sample_id)`. `PB90` and `CU90` are summary results, not individual household samples. Missing sample-period joins retain the result with unknown dates and a notice. No date-filtered claim includes an unjoined period as if its date matched. Do not derive compliance from a numeric summary or apply a present action level retroactively.

Enforcement retrieves actions, then `VIOLATION_ENF_ASSOC` filtered by PWSID and action/violation keys. Show originator/action codes and source text, not a generalized “federal penalty” label. Association pagination is independent through `section=associations`; summary counts are optional until fully counted. Snapshot quarter is preserved on associations. No cross-product of actions and violations is exposed as extra action rows.

Actions accept reported-state and county membership through the same resolved PWSID batches as violations, requiring PWSID or state. Associations and violation-ID filters require PWSID; any supplied geography still intersects that system. Association sections reject action/date predicates. Action-type matching is exact and case-insensitive over the complete published code, including punctuation. For a grammar-unsafe code, push `beginsWith` on its leading safe run or omit the predicate, then filter the full code locally before buffering or counting. Preserve unknown code pass-through and control-character rejection; dictionary lookup never interpolates action codes.

### UCMR retrieval

For UCMR, a valid service ZIP alone satisfies scope and resolves through archive membership without SDWIS requests. If PWSID or state is also supplied, intersect it with ZIP membership; county still requires state. Missing all scope selectors, malformed ZIPs and ZIP on other datasets fail before upstream requests. ZIP is service membership, not sample location.

One archive loader per process revision, admitted atomically. Use a shared abort controller with reference-counted waiters: caller cancellation detaches that caller; when no waiters remain, abort download/parse. Download is awaited and bounded by a 180-second total deadline; a cold call that cannot complete inside its budget returns retryable `dataset_loading` only if another live caller still owns the load, never detached background work. Normal read calls use a 45-second budget; document that first archive acquisition may require a 180-second client timeout.

Build a contact-free typed columnar index: dictionary-encode repeated strings into Uint32 indices, store dates as Int32 day ordinals, numeric measurements as Float64 with validity bitmaps, and keep source-order row IDs in bounded membership indexes. Do not allocate two million JavaScript row objects or duplicate arrays for every predicate combination. At roughly 24 four-byte columns plus two eight-byte measurements, two million rows need about 224 MB before dictionaries/indexes; measure actual retained allocations, dictionary bytes and parser working buffers against the 512 MiB index budget. Keep the companion relations within that budget, decode incrementally, and reconstruct only selected output rows. An implementation that exceeds the budget fails the readiness gate rather than silently dropping columns or rows.

Six-hour freshness is checked by the next awaited request, not a detached timer. Acquire a revision read lease; revalidate by HEAD/conditional GET under the shared loader before issuing new leases. Unchanged metadata extends freshness; missing validators require a download and SHA-256 comparison. For a changed revision, wait for old readers within the caller deadline, then release the old index before building its replacement; never hold two full indexes under a one-index budget. Active readers finish against their old hash, and later old-hash cursors fail `source_changed`. Teardown aborts and awaits the loader. Every result carries archive URL, hash, Last-Modified when present, retrieved time, and published final-release label separately.

UCMR pagination has stable source row offsets within an archive hash. Continuations retain only active step positions; repeated requests for the same active position reuse a pointer, and successful advancement removes obsolete pointers. A failed or cancelled operation leaves its retry position valid. Every validated use refreshes the source job's idle TTL, including membership, previews and retries. `detected_only=true` means sign `=` with a numeric value; it never treats `<MRL` as zero. Preserve additional data and ZIP membership as separate canvas relations when staging; ordinary result retrieval returns only requested occurrence items. Describe exposes the companion relation keys and caveats.

## DataCanvas capability and lifecycle

Enable through framework `CANVAS_PROVIDER_TYPE=duckdb`, install `@duckdb/node-api`, and wire `core.canvas` through `setup()` to a canvas service. No local shared-canvas ID, no “default tenant” metadata scan, no storage lookup that discovers other callers' canvases. `canvas_id` possession is the capability under HTTP auth none; it is required for every query, describe and drop, optional only for a producer minting a new canvas. Use framework `CanvasIdSchema` exactly, not a table-name-shaped substitute.

Bound the service to 8 active canvases process-wide, 16 tables per canvas, 250000 staged source rows per canvas, 512 MiB engine memory per canvas, one staging/query operation per canvas, and two concurrent canvas operations process-wide. Reserve capacity synchronously under a process-local admission mutex **before** awaiting mint/registration. Pending reservations count toward every cap. Mint and publish the capability only after a slot is held; rollback reservations on every error. Release operation reservations in `finally`; reconcile expiry/drop with the same lock. Per-canvas operation queues are bounded at 4 and cancellation removes queued entries. Never check a count, await, and mint without a reservation. Framework caps supplement these server limits; they do not replace atomic admission.

Each producing call with `stage=true` stages a bounded partition and returns an inline preview plus a dataset manifest. Do not use spillover to hide a partial source behind “full set staged.” Register explicit column schemas, including nullable DOUBLE measurement columns, never infer from leading null/zero rows. Name tables with a server-minted opaque suffix and semantic prefix (`violations_`, `lcr_results_`, `ucmr5_results_`, etc.). Track lineage in a bounded in-memory Map keyed by `(tenant,canvas_id,table_name)`, with source filters, query times, source offsets, row counts, completeness, continuation, parent partitions and schema. No user-data store writes. Reads acquire only the explicit capability, then inspect its own catalog. TTL/restart invalidates handles; provenance expires with its table.

Staging drains the selection beyond the inline limit until source exhaustion, `stage_max_rows`, the source-loop page threshold, or the shared deadline; it is never limited to the first ten preview rows. Membership checkpoints return no staged table or no-matches notice; only resolved source work can produce a partition, including a genuinely empty exhausted selection. Return continuations at exact unconsumed source offsets, including filtered-page state. A caller can exhaust a scoped multi-year selection by following source continuations into the same canvas and querying the returned partitions with `UNION ALL`. The 250000-row/16-table bounds are explicit scope limits, not a national bulk promise: larger requests remain partial and should be split by PWSID, contaminant or date range into separately completed analyses. Companion UCMR tables consume table and row capacity too; filter them to the staged occurrence keys, retain every matching companion row, and fail the partition atomically if all required relations cannot fit. A staging timeout after a valid bounded partition returns it with a continuation; cancellation never publishes partial registration.

Each retrieval has a distinct `selection_id`, even when its filters equal another retrieval's. Source `selection_partition` carries that identity, its zero-based delivered `partition`, and `final_partition` once exhaustion is known. Empty membership checkpoints do not advance the source sequence; inline delivery does, leaving a gap if later partitions are staged. An exhausted empty selection can be staged as partition zero. Replays retain their sequence rather than creating coverage for a missing partition.

Describe and query expose canvas-wide `selection_coverage` entries with `selection_id`, `partitions_present`, `final_partition`, and `chain_complete`. A partition is present only while every required relation remains live, including empty UCMR companions. Derive coverage from table lineage; missing, dropped, or expired relations prevent completion. `chain_complete` requires every partition from zero through observed exhaustion. It describes source acquisition, not SQL table references, result truncation, or an atomic EPA snapshot. Retained query results snapshot coverage alongside provenance, so replay after a table drop keeps the original evidence.

Use a one-hour per-table TTL through `registerTable({ttlMs})`; canvas TTL and absolute cap follow existing framework settings and their actual configured values. Describe uses authoritative engine schemas/counts and current expiry, reconciles metadata only within the explicit canvas, and does not fabricate size estimates. Rely on framework in-flight lifecycle handling; the server operation reservation serializes its own drop/registration. Failure/cancellation drops tables created by that failed partition and returns no incomplete handle; earlier successful partitions remain valid. A continuation registers a new partition, never appends duplicate rows to an old one. The producer manifest names the primary table; describe lists live partition and companion names with their relation and lineage. Use SQL `UNION ALL` explicitly to combine partitions. Automatic union-view management adds lifecycle coupling without earning its cost for at most 16 tables. `source_complete` remains conservative across multiple partitions; `selection_coverage` reports retrieval-wide acquisition separately. Capacity exhaustion rejects the new partition with narrower-scope guidance and leaves prior partitions intact.

Every output containing `canvas_id`, including dataframe tools, carries this exact pointer text: “Use sdwis_dataframe_describe with this canvas_id to inspect table names and columns, then sdwis_dataframe_query with this canvas_id to analyze the staged rows.” Dataset handles include `table_name`, `row_count`, `source_complete`, `expires_at` and any partition continuation alongside it; describe/query/drop retain their own output shapes. An unavailable canvas never yields a fake handle or an inline-success fallback for a requested stage.

Describe pages whole tables with one `columns` array and one copy of each table's metadata. Authenticated describe positions bind the explicit canvas, tenant, exact table selector and stable live identity: table membership, rows, schema and lineage. Sliding expiry is excluded from identity, so a SELECT-driven TTL extension does not invalidate the continuation. Retain the original deadline (at most fifteen minutes or the earliest table expiry when issued), report current authoritative expiry, and enforce actual table/canvas expiry. Re-read live metadata on continuation and reject membership, schema or lineage changes rather than retaining a second metadata cache.

### SQL

Call `instance.query` with `signal` and `denySystemCatalogs:true`. Rely on the framework's statement-count/type, denied file/network functions, read-only preparation and plan gates plus engine filesystem boundary. Do not write a second SQL regex parser. Allow one SELECT-shaped statement (including WITH/FROM forms the framework permits), no file/HTTP access, ATTACH/COPY, extension loading, multiple statements or system catalogs. No user-controlled export/import path or `register_as` field is exposed.

Use `instance.query` directly with a row limit equal to the lesser of the configured framework ceiling and 25000, then page whole returned rows by count. The framework default is 10000; `CANVAS_DEFAULT_ROW_LIMIT` can change that ceiling. Retain the bounded returned result in a process-memory query cache (15-minute TTL, 16 entries and 32 MiB process-wide) for immutable pagination, binding cursor to canvas, SQL and cache entry. Reserve bytes/entries before publishing a cursor; refuse with capacity guidance if the result cannot be retained. Do not create hidden DuckDB result tables, wrap user SQL, or add a query materialization layer. Report framework `rowCount`, returned-row count and truncation separately; a cursor reaches retained rows only, and truncation guidance states the effective cap and asks for narrower SQL to retrieve omitted rows. Conservatively inherit source incompleteness from every live table in the canvas; this avoids implementing a SQL lineage parser and may overstate incompleteness, which the response explains. Query paging does not claim source completeness simply because an aggregate returns one row.

Query continuations authenticate retained-entry identity and row positions without retaining a separate pointer map. Replay remains valid through the original result expiry, including after source-table removal, and never re-executes SQL.

Missing tables use framework `missing_table`, unknown/expired capabilities use `canvas_not_found`, malformed IDs fail argument validation. Keep engine conversion/binder/parse failures distinct from database/IO faults. Do not catch every engine exception and relabel it bad SQL.

For known typed caller-correctable SQL errors, preserve framework reason/code, path-redacted diagnostic messages and relevant structured details such as `binderMessage` and `function`, while adding server-specific recovery guidance. Preserve Unicode diagnostics without truncation or repeated SQL in recovery fields. Raw causes, stacks and unknown database/engine failures remain internal; unclassified failures use generic diagnostics.

### Disabled capabilities and MCPB

With `CANVAS_PROVIDER_TYPE=none`, register dataframe query/describe/drop as disabled definitions with the enable hint; producer inline reads remain available. Drop requires both canvas and `SDWIS_DATAFRAME_DROP_ENABLED=true`, parsed with `z.stringbool()`. Capacity/recovery guidance always leads with reusing a held ID, waiting for expiry, or narrowing a selection. Include a structured drop suggestion only when that tool is callable. A missing canvas on drop returns `dropped:false` with “No staged table remains to remove”; do not ask the caller to re-stage merely to delete it.

The MCPB cleaner strips DuckDB native dependencies. Explicitly ship MCPB with `CANVAS_PROVIDER_TYPE=none` in its launch environment and no canvas toggle in its settings; document npm/Docker as the route for SQL staging. The six EPA-reading tools still work in MCPB. `stage=true` returns `canvas_disabled` with that runtime explanation. Do not advertise MCPB SQL support without shipping and testing native bindings for every supported architecture. npm/Docker enable canvas only when the configured engine and native dependency are available; initialization fails clearly rather than silently pretending it is enabled.

## Services, resilience and configuration
